# Transport Navigator

## Описание проекта

**Transport Navigator** — это десктопное приложение для построения мультимодальных маршрутов в городе. Приложение позволяет находить оптимальные пути от точки А до точки Б с использованием различных видов транспорта (пешком, автомобильб такси, автобус, метро) и учетом динамических факторов, таких как время суток, расписания и временные ограничения (например, разводные мосты).

Основной фокус проекта — разработка чистого, расширяемого и производительного бэкенда на современном C++ с применением паттернов проектирования SOLID, GRASP и GoF.

## Функциональные требования

1.  **Мультимодальный граф:**
    *   Поддержка нескольких типов рёбер: пешеходные дорожки, автомобильные дороги, автобусные маршруты, линии метро.
    *   Поддержка узлов-пересадок (например, от остановки до входа в метро).
2.  **Поиск маршрута:**
    *   Реализация алгоритма A* для эффективного поиска пути.
    *   Возможность поиска по нескольким критериям (стратегиям):
        *   **Самый быстрый:** Минимизация общего времени в пути.
        *   **Самый дешёвый:** Минимизация суммарной стоимости (билеты, топливо), но пешком надо считать стоимость не в рублях, а в единицах усталости - учитывается при подсчете стоимости маршрута, но не в итоговой сумме.
        *   **Самый удобный:** Минимизация количества пересадок.
3.  **Динамические условия:**
    *   **Расписание автобусов:** Алгоритм должен учитывать, что автобус доступен только в определенное время на конкретной остановке (с момента прибытия на остановку до момента отправления с неё).
    *   **Метро** Поезда метро ходят с интервалом 2 минуты утром и вечером (6:00-10:00 и 17:00-21:00) и 5 минут днём (10:00-17:00)
    *   **Разводные мосты:** Некоторые рёбра графа (мосты) должны быть недоступны для проезда в ночное время (1:00-5:00).
    *   **Текущее время:** Приложение должно использовать системное время (или заданное пользователем) для расчетов.
4.  **Пользовательский интерфейс (UI):**
    *   (Stretch goal) Графический интерфейс с интерактивной картой.
    *   Визуализация графа (узлы и рёбра).
    *   Выбор начальной и конечной точек кликом или через ввод адреса.
    *   Отображение нескольких предложенных маршрутов с краткой сводкой (время, цена, пересадки).
    *   Подробная пошаговая инструкция для выбранного маршрута.
5.  **Доступные способы перемещения:**
    *   Собственный автомобиль (надо рассчитать стоимость топлива).
    *   Автобус (надо рассчитать стоимость билета, стоимость билета не зависит от длины поездки).
    *   Метро (надо рассчитать стоимость билета, стоимость билета не зависит от длины поездки).
    *   Пешком (надо считать стоимость не в рублях, а в единицах усталости - учитывается при подсчете стоимости маршрута, но не в итоговой сумме)
    *   Такси (равносильно личному автомобилю, но стоимость топлива - это стоимость поездки)

## Архитектура и технические решения

### 1. Backend (C++ Core)

#### Структура данных графа

Граф будет храниться в памяти (in-memory) в виде списка смежности.

*   **`Graph`**: Шаблонный класс, реализующий базовую структуру графа.
    *   `std::unordered_map<NodeId, Node>` — хранилище узлов.
    *   `std::unordered_map<NodeId, std::vector<Edge>>` — список смежности.
*   **`Node`**: Структура, представляющая узел (перекресток, остановка, станция метро).
    *   `NodeId id`: Уникальный идентификатор.
    *   `Point coordinates`: Координаты (x, y) для UI и эвристики A*.
    *   `NodeType type`: Тип узла (e.g., `Intersection`, `BusStop`, `MetroStation`).
*   **`Edge`**: Структура, представляющая ребро (путь между узлами).
    *   `EdgeId id`: Уникальный ID ребра для связи с расписаниями.
    *   `NodeId from, to`: Идентификаторы узлов.
    *   `std::string name`: Название (номер маршрута, улица).
    *   `TransportType transport`: Тип транспорта.
    *   `double length_meters`: Длина ребра в метрах.
    *   `std::unique_ptr<ITimeVariant> time_variant_logic`: Указатель на объект, инкапсулирующий динамическое поведение.

#### Динамические рёбра (Паттерн Strategy/Decorator)

Для реализации расписаний и разводных мостов будет использован интерфейс `ITimeVariant`. Вместо простого `getArrivalTime` интерфейс должен возвращать и время, и **стоимость**, потому что стоимость тоже может быть динамической (например, "ночной тариф" или ожидание).


```cpp
// Контекст запроса, содержащий время отправления от начального узла ребра
struct QueryContext {
    std::chrono::system_clock::time_point departure_time;
};

// Структура для комбинированной стоимости, как мы обсуждали
struct CombinedCost {
    double money = 0.0;
    double fatigue = 0.0;
    int transfers = 0;
    // ... перегруженные операторы + и > ...
};

// Интерфейс для рёбер с поведением, зависящим от времени
class ITimeVariant {
public:
    virtual ~ITimeVariant() = default;

    // Рассчитывает время прибытия в конечный узел и стоимость прохождения ребра.
    // Если ребро недоступно в данный момент, возвращает std::nullopt.
    virtual std::optional<std::pair<std::chrono::system_clock::time_point, CombinedCost>>
        calculate(const Edge& edge, const QueryContext& ctx, const IRouteStrategy& strategy) const = 0;
};
```

*   **`StaticLogic`**: Для пеших и автомобильных дорог (время и стоимость рассчитываются по скорости и длине).
*   **`ScheduledLogic`**: Для автобусов (находит ближайшее отправление, добавляет время ожидания к стоимости).
*   **`FrequencyBasedLogic`**: Для метро (рассчитывает среднее время ожидания на основе интервала, добавляет его к стоимости).
*   **`TimeWindowLogic`**: Для разводных мостов (проверяет, входит ли время в разрешенный интервал).

#### Алгоритм A*

Алгоритм будет реализован как шаблонная функция, принимающая на вход граф и **эвристику**. Эвристикой будет евклидово расстояние между текущей точкой и целью, умноженное на среднюю скорость.

#### Критерии поиска (Паттерн Strategy)

Для поиска по разным критериям (время, стоимость, пересадки) будет применен паттерн **Strategy**. Алгоритм A* будет параметризоваться структурой, определяющей вес ребра. Стратегия не просто считает вес, она должна уметь **создавать** вес (`CombinedCost`) для разных типов ребер.

```cpp
// Интерфейс стратегии поиска
class IRouteStrategy {
public:
    virtual ~IRouteStrategy() = default;
    
    // Создает объект стоимости для конкретного ребра и контекста.
    // Эта стоимость может быть временем, деньгами, пересадками или их комбинацией.
    virtual CombinedCost create_cost(const Edge& edge, 
                                     const TransportParams& params, 
                                     std::chrono::seconds wait_time) const = 0;
    
    // Эвристическая функция для A*
    virtual CombinedCost heuristic(const Node& from, const Node& to) const = 0;
};

// --- Реализации ---
class FastestStrategy : public IRouteStrategy { /* ... */ };
class CheapestStrategy : public IRouteStrategy { /* ... */ };
class MostConvenientStrategy : public IRouteStrategy { /* ... */ };
```
*Это более чистая архитектура: алгоритм A* работает с `IRouteStrategy` и `ITimeVariant`, ничего не зная о конкретных типах транспорта.*


#### Загрузка графа (Паттерн Builder)

Граф будет загружаться из CSV-файлов с помощью паттерна **Builder**. Это позволит отделить процесс конструирования графа от его представления.

**Формат CSV-файлов:**

1.  **`nodes.csv`**:
    *   `node_id (int), x (float), y (float), type (string: "stop", "intersection", "metro"), name (string)`
    *   Пример: `101,55.75,37.61,"stop","Остановка 'Красная Площадь'"`

2.  **`edges.csv`**:
    *   `from_id (int), to_id (int), transport (string: "walk", "car", "bus"), length (float)`
    *   Пример: `101,102,"walk",150.0`

3.  **`transport_params.csv`**:
    *   `transport_type (string), param_name (string), param_value (float)`
    *   Примеры: `walk,speed_kmh,5.0`,
                `walk,fatigue_per_km,10.0`,
                `car,speed_kmh,40.0`,
                `car,fuel_consumption_l_per_100km,8.0`,
                `car,fuel_price_rub_per_l,50.0`,
                `bus,speed_kmh,25.0`,
                `bus,ticket_price,55.0`,
                `metro,speed_kmh,50.0`,
                `metro,ticket_price,55.0`,
                `metro,morning_evening_interval_min,2.0`,
                `metro,day_interval_min,5.0`,
                `taxi,price_per_km,20.0`,
                `taxi,base_price,150.0`

4.  **`schedules.csv`**:
    *   `edge_id (соответствует ребру из edges.csv), departure_times (string: "08:00,08:15,08:30,...")`

### 2. Frontend (UI) - Stretch Goal

*   **ImGui**: Легковесный, отлично подходит для быстрых прототипов и оверлеев.

**Взаимодействие Backend и Frontend:**
Будет реализован паттерн **Facade** (или Controller). Класс `NavigationFacade` будет предоставлять для UI простые методы:
*   `findRoutes(start_coords, end_coords)`
*   `getGraphDataForRendering()`

**Это позволит полностью отделить C++ логику (которая сдается на оценку) от UI.** Можно будет собрать проект в консольной версии, где все работает через командную строку.

## Паттерны проектирования (GoF) и принципы SOLID/GRASP

*   **SOLID:**
    *   **S (Single Responsibility):** Классы `Graph`, `AStarSolver`, `CsvLoader` отвечают каждый за свою задачу.
    *   **O (Open/Closed):** Добавление нового вида транспорта или нового критерия поиска (например, "самый экологичный") не потребует изменения существующего кода, а лишь добавления новых классов-стратегий.
    *   **L (Liskov Substitution):** Все `ITimeVariant` должны быть взаимозаменяемы.
    *   **I (Interface Segregation):** Не создаем "толстых" интерфейсов.
    *   **D (Dependency Inversion):** Алгоритм A* зависит от абстракции `IEdgeWeightPredictor`, а не от конкретной реализации.
*   **GRASP:**
    *   **High Cohesion / Low Coupling:** Достигается за счет разделения на модули (ядро графа, алгоритмы, загрузчики).
    *   **Information Expert:** Класс `ScheduledEdge` является экспертом в расчете времени прибытия для автобуса.
*   **GoF:**
    *   **Strategy:** Двойное применение!
        1. `IRouteStrategy` для выбора глобального критерия поиска (быстро, дешево, удобно).
        2. `ITimeVariant` для выбора локальной логики поведения ребра (расписание, интервал).
    *   **Builder:** Построение сложного объекта графа из CSV.
    *   **Facade:** Предоставление простого интерфейса для UI.
    *   **Factory Method (неявно):** Внутри `Builder`'а будет фабричный метод для создания нужного `ITimeVariant` на основе данных из `schedules.csv`.
